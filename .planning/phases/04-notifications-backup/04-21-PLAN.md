<objective>
Ride-along WR-06 and WR-07, both defects in the notification permission flow.

WR-06: `startNotifications()` documents that the permission prompt is never raised at launch,
but the on-open goal evaluator (D-06: evaluated on app open) reaches
`ImmediateAlertDispatcher.dispatch`, which calls `PermissionGate.ensureAsked()`. With any
off-track goal (the kind is on by default) a fresh install shows the system dialog over the
first frame, and a refused prompt would have suppressed the goal's alert for the whole week.

WR-07: once the OS stops showing the dialog (Android 13+ after the second refusal, iOS after
the first) the settings banner's "Allow notifications" button does nothing and there is no
route to the system settings. Add one tiny platform channel and make the banner flip to
"Open settings" after a refused request.

NOTF-06 is the goal off-track alert; NOTF-01 stands for every reminder, all of which need the
permission this banner restores.

The string "Open settings" already exists from plan 04-18; this plan does not edit ARB or
generated l10n. Plan 04-18 owns the iOS exclusion code in AppDelegate.swift; this plan only
adds a channel next to it.
</objective>
