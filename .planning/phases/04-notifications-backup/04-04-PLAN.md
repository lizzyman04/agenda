<objective>
Build the JSON export engine for DATA-02: explicit, versioned codecs over the seven Isar
models, a single-transaction uncapped reader, the envelope, and `exportJson` on a new
`BackupRepository`. The same codecs include strict decoders so plan 04-11 (import)
reuses them and a round-trip test can prove fidelity now.

Purpose: JSON is the full, versioned backup/restore format (D-10). Explicit codecs
(not Isar's own exportJson) keep the file format independent of Isar field renames, and
the uncapped single-transaction read keeps a backup from being silently truncated by the
`.limit(500)` class of defect that already burned this project twice (CR-04, BL-01).

Output: the engine and its tests. The file-picker gateway, cubit and screen are plan
04-16; CSV is plan 04-08.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Isar (private app storage) -> exported bytes | All user data becomes a plaintext JSON byte array that the caller (plan 04-16) writes to a user-chosen location. |
| Decoder input (later: untrusted file) -> in-memory models | The decoders written here are what plan 04-11 points at hostile files. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-04-01 | Information disclosure | Export contents are unencrypted | medium | accept | Documented in the UI privacy note (backupPrivacyNote): the file lives wherever the user saves it; no custom crypto is introduced (ASVS V6 level 1). |
| T-04-04-02 | Information disclosure | Logging of export content | medium | mitigate | The repository never logs payload bytes or field values; failures log only a message string. |
| T-04-04-03 | Tampering | Decoders fed attacker-controlled JSON | high | mitigate | JsonObjectReader enforces int/string/bool/enum/date typing, a 20000-character string cap and a 9e15 integer bound, and throws FormatException with the field path; the import engine (04-11) adds file-size and row-count caps and runs all validation before any write. |
| T-04-04-04 | Denial of service | Large collections encoded on the UI isolate | low | accept | Single-user, on-device; the export is user-initiated and bounded by the user's own data. |
</threat_model>
