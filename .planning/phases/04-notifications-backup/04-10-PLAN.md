<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| OS notification tap -> app | The platform returns a payload string on tap; it is untrusted until parsed (strict grammar, plan 04-03). |
| Notification shade / lock screen | Notification content is displayed outside the app, possibly while locked. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-----------|-----------------|
| T-04-10-01 | Information disclosure | Notification content on a locked screen | medium | mitigate | All channels use NotificationVisibility.private; content strings carry no amounts (plan 04-02); documented limitation that OEM lock-screen behaviour (assumption A17) needs device UAT. |
| T-04-10-02 | Spoofing | Tap payload | medium | mitigate | tapPayloads forwards the raw string only; parsing and entity re-validation happen in the tap router (plan 04-13) using the strict decodePayload. |
| T-04-10-03 | Denial of service | One failing schedule aborting the batch | medium | mitigate | Each plugin call is individually wrapped and returned as Err(NotificationFailure); the coordinator continues with the next item. |
| T-04-10-04 | Repudiation / privacy | Permission prompt at launch | low | mitigate | Darwin request flags false; Android 13 request is made in context by the gate (04-12) and settings cubit (04-15), never from initialize(). |
</threat_model>
