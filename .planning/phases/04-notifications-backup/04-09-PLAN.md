<objective>
Add the data-layer reads and reactive streams the notification coordinator and the budget
evaluator need: an uncapped, sorted "soonest N" reminder query, an uncapped due-date
window query for briefing counts, and `watchChanges()` on the budget and recurring-payment
repositories.

Purpose: the existing item queries all apply `.limit(500)` without a sort (the BL-01 /
CR-04 defect class that already silently corrupted money totals twice). Reminders and the
briefing must not silently ignore tasks beyond row 500. Research Pitfall 2 requires
dedicated methods and a real-Isar regression test.

Output: two query functions, repository interface additions, `watchChanges` plumbing,
stub updates, and real-Isar tests. No notification logic here.
</objective>
