<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| App-private backups directory -> user-chosen location | A saved copy leaves the private directory at the user's explicit request through the system dialog. |
| Backups directory contents -> delete action | The delete must only remove files this app generated. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-----------|-----------------|
| T-04-20-01 | Information disclosure | Plaintext safety copies persist with no way to remove them | medium | mitigate | "Delete all" with confirmation removes every generated-name file; count refreshes after each import. |
| T-04-20-02 | Tampering | deleteAll removing files the app did not create | medium | mitigate | listing and deletion match only the generated name pattern; unrelated-file survival is tested at store and repository level. |
| T-04-20-03 | Information disclosure | Safety backup routed to other apps | medium | mitigate | Saving uses BackupFileGateway.saveFile (system save dialog); no share_plus (D-12); no path or name is displayed. |
| T-04-20-04 | Repudiation / data loss | Accidental deletion of the only recovery copy | medium | mitigate | Confirmation dialog states what is removed and that current data is unaffected. |
| T-04-20-05 | Information disclosure | Error text leaking file details | low | mitigate | Repository failures carry only the exception type; the UI shows fixed localized messages. |
</threat_model>
