WR-01 (blocker): every CSV mapper decodes a blank id as `Isar.autoIncrement`; `putAll` in file
order lets an auto id equal a later explicit id and the later row silently overwrites it. The
verifier reproduced counts=3 with only 2 rows stored. Fix by assigning ids deterministically
before `putAll` (D-11: the replace stays one atomic transaction; D-14: CSV still replaces only
the supplied entities) and make any residual loss loud by checking the stored row count inside
the transaction.

WR-03: `lastSafetyBackupPath` survives a failed export or write and is reported as the
recovery location for a backup that was not made (D-12 says the path is shown if import
fails, so it must be the right one). WR-05: a rotation failure aborts the import after the
backup was written. WR-08: picked files stay in the plugin cache and there is no file-count
or total-size cap.

IN-01..IN-08. The safety-backup management UI (WR-04) is plan 04-20.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| User-edited CSV / JSON file -> import pipeline | Untrusted rows, including blank or colliding ids. |
| File picker plugin cache -> app memory | Plaintext user data is copied to cache, then read fully into memory. |
| Safety-backup store -> import commit | Housekeeping must not decide whether an import happens. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-----------|-----------------|
| T-04-19-01 | Tampering | BackupImporter.replace with mixed blank and explicit ids silently overwriting rows | high | mitigate | assignMissingIds before putAll plus an in-transaction stored-count check that aborts the import; regression tests in import_atomicity_test and import_flow_test. |
| T-04-19-02 | Repudiation | Preview and result report counts that the database does not hold | medium | mitigate | Counts are verified against count() per collection before the transaction commits. |
| T-04-19-03 | Information disclosure | Plaintext copies of picked files left in the plugin cache | medium | mitigate | FilePicker.clearTemporaryFiles in a finally after reading, on every path. |
| T-04-19-04 | Denial of service | Many or very large files read fully into memory and decoded to strings | medium | mitigate | importLimitViolation (6 files, 25 MiB each, 50 MiB total) before reading, enforced again in parseBackupFiles. |
| T-04-19-05 | Information disclosure | Misleading recovery path pointing at a backup that was not made | low | mitigate | lastSafetyBackupPath reset at the start of every commit. |
| T-04-19-06 | Denial of service | Rotation deletion error refusing a valid import | low | mitigate | Rotation failures are swallowed after the new backup is written. |
</threat_model>
