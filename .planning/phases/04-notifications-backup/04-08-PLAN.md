<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| App data -> CSV opened in a spreadsheet application | Cell contents are interpreted by Excel/LibreOffice, which executes formulas. |
| CSV file (user-supplied or hand-edited) -> decoder | The decode side parses untrusted text. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-----------|-----------------|
| T-04-08-01 | Tampering | CSV formula injection via task title or note (e.g. =HYPERLINK) | high | mitigate | guardCsvText prefixes an apostrophe to text cells starting with = + - @ tab or CR; lossless unguard on import; round-trip test with a hostile title. |
| T-04-08-02 | Tampering | Hostile or malformed CSV (huge file, wrong cell counts, huge fields, number overflow) | high | mitigate | Row cap 100000, string cap 20000, 13-digit amount cap, strict amount grammar, FormatException with row and column; plan 04-11 adds the file-size cap before decoding and runs all validation before any write. |
| T-04-08-03 | Information disclosure | Plaintext CSV in user storage | medium | accept | Documented in backupPrivacyNote; location chosen by the user via the system dialog (D-12). |
| T-04-08-04 | Tampering | Silent sign flip of a negative amount | medium | mitigate | parseAmountCell rejects any sign; the legacy form parser with the known flip is not reused (asserted by grep). |
</threat_model>
