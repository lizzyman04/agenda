<objective>
Finish DATA-04 on the user side: pick a file, review a confirmation screen with counts and
date range, commit through the safety backup and atomic transaction (plan 04-11), then
reseed alert state and reconcile notifications.

Purpose: SC-5 requires a confirmation screen, an automatic safety backup and an atomic
import where a failure leaves the database unchanged. D-12 says the safety backup path
must be shown if the import fails; D-14 says CSV replaces only the supplied entity types.

Output: cubit extension, confirmation screen, summary card, error-text mapper, backup
screen import card, DI regeneration and tests. This is the last plan of the phase; its
human checks consolidate the device UAT.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| User-selected file -> import pipeline | Entirely untrusted content (validated by plan 04-11). |
| Confirmation screen -> destructive replace | A user mistake can destroy current data; the safety backup is the recovery path. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-----------|-----------------|
| T-04-17-01 | Tampering | Malicious backup file | high | mitigate | Plan 04-11 validation and caps run in prepare; this plan shows only localized, code-mapped messages and never raw exception text. |
| T-04-17-02 | Repudiation / data loss | Confirming an import by mistake | high | mitigate | Mandatory confirmation screen with counts and date range; safety backup created before replace and its path shown on failure (D-11, D-12). |
| T-04-17-03 | Information disclosure | Safety backup path displayed to the user | low | accept | The path is inside the app-private directory; showing it is a stated requirement (D-12). |
| T-04-17-04 | Denial of service | Alert storm or stale schedule after restore | medium | mitigate | Silent reseed of budget and goal markers then an afterImport reconcile; hooks isolated by try/catch. |
</threat_model>
