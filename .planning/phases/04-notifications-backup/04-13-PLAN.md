<objective>
Make notification taps land somewhere useful and keep the shell testable: a pure tap
target resolver, a listener widget mounted inside the app shell, tab and sub-tab
navigation through shared notifiers, and a locale-change reconcile hook. The bottom-nav
shell moves out of `app.dart` so it can grow without breaching the 150-line cap.

Purpose: tap-through navigation targets are a Claude's-discretion item in CONTEXT; the
research table fixes the mapping. The payload is parsed with the strict codec and the
referenced entity is re-checked before navigating (spoofing mitigation).

Output: resolver, listener, navigator, shell extraction, finance sub-tab hook and tests.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| OS -> app via notification tap | Payload string is attacker-influenceable only via other apps' intents; it must be validated like input. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-----------|-----------------|
| T-04-13-01 | Spoofing | Crafted payload opening an arbitrary screen or id | medium | mitigate | Strict decodePayload grammar and kind whitelist; ids are only used to load the entity, which is re-checked for existence and deletedAt; unknown input maps to AppOnly. |
| T-04-13-02 | Denial of service | Rapid taps or payload loops | low | accept | Each tap is an independent navigation; no persistent state is written by routing. |
| T-04-13-03 | Elevation of privilege | Notification receivers reachable by other apps | high | mitigate | Receivers are exported=false (plan 04-05); the app reads taps only through the plugin callback. |
</threat_model>
