Split the three smallest presentation/finance violations by extracting each screen's single self-contained private widget class. New files go into per-entity subfolders under `presentation/finance/widgets/` (`widgets/debt/`, `widgets/recurring/`, `widgets/budget/`) rather than the flat `widgets/` root — the root currently holds 6 files and this phase's other plans (`3.1-08`, `3.1-10`, `3.1-12`–`3.1-15`) add several more; without per-entity subfolders the root would exceed the 10-file cap and this refactor would create a *new* SC-2 violation. `presentation/finance/screens/` itself is untouched (no screen file moves) — only new widget files are added under `widgets/`, so no other plan's import of these screens is affected.

</objective>
