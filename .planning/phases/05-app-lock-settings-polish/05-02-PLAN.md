failed-attempt ladder and the D-01/D-02/D-03 resume-lock decision. Both are pure Dart
functions over an injected `now`, so every boundary can be pinned exactly by unit tests.

the timeout rule (RESEARCH Pattern 5 threat-model note); getting a boundary wrong silently
weakens DATA-05.

Output: lib/domain/lock/lock_attempts.dart, lib/domain/lock/lock_policy.dart and their tests.
No dependency, no DI, no Flutter import, so this plan runs in Wave 1 beside 05-01.

    const LockAttempts({int failures = 0, int lockouts = 0, DateTime? cooldownUntil})
    static const LockAttempts none
    static const int maxFailuresBeforeCooldown = 5
    static const List<Duration> cooldownLadder = [30 s, 1 min, 5 min, 15 min]

    static const int defaultTimeoutSeconds = 60
    static const int excursionCapSeconds = 300
    static int effectiveTimeoutSeconds(int? stored)
  bool shouldLockOnResume({required DateTime? hiddenAt, required DateTime now,
      required int timeoutSeconds, required bool hiddenDuringExcursion})
