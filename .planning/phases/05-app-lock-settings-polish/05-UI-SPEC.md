# Phase 05 — UI Design Contract: App Lock + Settings + Polish

> Visual and interaction contract for Phase 5 screens: lock screen, PIN setup, privacy overlay,
> Settings, first-launch privacy statement, and the remaining empty states.
> Generated by gsd-ui-researcher, verified by gsd-ui-checker.
> **Flutter-specific:** every token is a Flutter/Dart value (logical pixels, `TextTheme` roles,
> `ColorScheme` tokens). There is no CSS, no Tailwind and no shadcn here.

**Baseline:** the approved Phase 3 contract (`.planning/phases/03-finance-core/03-UI-SPEC.md`) plus
the code as it stands. This phase adds new surfaces only. It does **not** restyle
`NotificationSettingsScreen` or `BackupScreen`, which are mounted unchanged (Phase 4 D-09).

**Why a custom keypad (discretion call):** D-07 needs an escalating cooldown (30 s → 1 min → 5 min → 15 min) that survives app kills, plus a live countdown on the keypad. `flutter_screen_lock` documents a retry limit, but not an escalating or persisted delay. The same keypad is also reused in four modes (unlock, create, confirm, verify current). A small custom widget built from Material primitives gives one visual language and full control over the cooldown display.

**Component Inventory:** omitted. `Tool: none` means there is no installed design-system package to enumerate. Use Flutter SDK Material widgets. The widget vocabulary below lists what each new surface uses, and it is not an allowlist.

**Architecture constraint (Phase 6, still binding):** every hand-written Dart file stays at or under 150 lines, and every new presentation nest gets a `README.md`. Suggested nests are `lib/presentation/lock/`, `lib/presentation/settings/` and `lib/presentation/onboarding/`, each with `screens/` and `widgets/`. Split the keypad, PIN dots, status line and biometric key into separate widget files.

## Spacing Scale

All values are logical pixels (`EdgeInsets` / `SizedBox`), multiples of 4.

| Token | Value | Usage in this phase |
|-------|-------|---------------------|
| xs | 4 | Section-header bottom padding (`EdgeInsets.fromLTRB(16, 16, 16, 4)`, the existing Settings/Notifications pattern) |
| sm | 8 | Gap between lock title and status line; between privacy headline and intro |
| md | 16 | Screen horizontal padding on Settings; gap between PIN dots; gap between keypad rows; gap between privacy bullets; icon-to-label gap in the privacy overlay |
| lg | 24 | Privacy screen horizontal padding; gap between status line and PIN dots; horizontal gap between keypad columns; gap above "Esqueci meu PIN"; bottom padding under the "Começar" button |
| xl | 32 | Gap between privacy intro and the bullet list; lock screen bottom padding |
| 2xl | 48 | Top spacer on the lock screen and privacy screen; gap between PIN dots and keypad |
| 3xl | 64 | Not used in this phase |

Exceptions:
- **Keypad key:** 72×72 circle (above the 48×48 Material touch minimum). The 3-column grid is 3×72 + 2×24 = 264 wide, so it fits a 320-dp screen with 28 dp margins.
- **PIN dot:** 16×16 circle, 2 dp outline when empty.
- **Lock status line:** fixed height 40 (two lines of 14/20 text) so error and cooldown messages never shift the dots or keypad.
- **Icon-to-text gap of 12** inside list rows and dialogs. This is inherited from the Phase 2/3 `_FieldRow` and `TaskListSettingsMenu` pattern, and Material `ListTile` applies it on its own.
- **Primary button height:** `FilledButton` minimum height 48, full width on the privacy screen (`minimumSize: Size.fromHeight(48)`).

## Color

Inherited M3 scheme from `ColorScheme.fromSeed(seedColor: Colors.deepPurple)`. No new color constants. `FinanceColors` is not used anywhere in this phase.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `cs.surface` | Scaffold background of Settings, lock screen, PIN setup, privacy screen; full-bleed privacy overlay |
| Secondary (30%) | `cs.surfaceContainerHighest` (keypad digit key fill), `cs.surfaceContainer` (dialogs, M3 default) | Keypad digit circles, AlertDialog/radio dialogs |
| Accent (10%) | `cs.primary` | Only the elements listed below |
| Destructive | `cs.error` | Wrong-PIN state and the "Desativar" confirm button only |
| Muted | `cs.onSurfaceVariant` | Subtitles, cooldown text, lock/overlay icons, bullet icons, backspace icon |
| Outline | `cs.outline` | Empty PIN-dot outline (2 dp) |

Accent (`cs.primary`) is used only for:
1. Filled PIN dots (lock screen and PIN setup)
2. Biometric key icon on the keypad (`Icons.fingerprint` on Android, `Icons.face` on iOS)
3. "Começar" / "Get started" `FilledButton` fill (privacy screen)
4. Privacy-screen hero icon (`Icons.shield_outlined`, size 64)
5. Active `Switch` thumb/track and selected `Radio`, using the M3 defaults in `SwitchListTile`/`RadioListTile`
6. `TextButton` label "Esqueci meu PIN" (M3 default `TextButton` color)

The SegmentedButton selected segment uses its M3 default `cs.secondaryContainer`, not primary. Settings section headers stay in the default `cs.onSurface`, not primary, to match `NotificationSettingsBody`.

`cs.error` is used only for:
1. The lock status line when it shows a wrong-PIN message (`lockWrongPin`), the PIN-mismatch message (`pinMismatch`), or a verification error (`lockErrorGeneric`)
2. All four PIN dots while the wrong-PIN shake plays (300 ms), after which they clear to empty
3. The `FilledButton` with `backgroundColor: cs.error` in the "Turn off PIN lock" dialog, the same pattern as `confirmDeleteSafetyBackups`

The cooldown message is **not** an error color. It uses `cs.onSurfaceVariant`, because it is a wait state, not a failure.

Bottom of list: `SizedBox(height: 32)`.

**Language dialog:** `AlertDialog(title: Text(l10n.settingsLanguageDialogTitle))`, content is two `RadioListTile<Locale>`: "Português (Brasil)" and "English". These are endonyms, identical in both locales. Selecting a radio calls `LocaleCubit.setLocale` and closes the dialog immediately with no confirm button. The whole app re-renders in the new language. Actions: one `TextButton(cancelButton)`.

**Timeout dialog:** `AlertDialog(title: Text(l10n.lockTimeoutDialogTitle))` with five `RadioListTile<int>` in this order: Imediatamente (0), 30 segundos (30), 1 minuto (60, default), 5 minutos (300), 15 minutos (900). Selecting one persists `StorageKeys.lockTimeoutSeconds` and closes. Actions: `TextButton(cancelButton)`.

### PinKeypad (shared widget)

```
          ●  ●  ○  ○             ← PinDots (16 dp, gap 16)

        (1)   (2)   (3)          ← 72 dp circles, column gap 24
        (4)   (5)   (6)            row gap 16
        (7)   (8)   (9)
       [bio]  (0)   [⌫]          ← bio / backspace: 72 dp transparent targets
```

| Element | Spec |
|---------|------|
| Digit key | 72×72 `Material(shape: CircleBorder(), color: cs.surfaceContainerHighest)` + `InkWell` ripple; label `headlineMedium` `cs.onSurface`; `HapticFeedback.selectionClick()` on press |
| Bottom-left key | Biometric key: `IconButton`-style 72×72 transparent target, `Icons.fingerprint` (Android) / `Icons.face` (iOS), size 32, `cs.primary`, tooltip `lockBiometricToggle`. Present only on the lock screen when biometrics are on and enrolled. Otherwise it is an empty 72×72 `SizedBox` so `0` stays centered. |
| Bottom-right key | Backspace: 72×72 transparent target, `Icons.backspace_outlined` size 24, `cs.onSurfaceVariant`, tooltip `lockDeleteDigit`. Removes the last digit. Long-press clears all digits. Disabled when no digits are entered. |
| PIN dots | Row of 4, 16×16 circles, gap 16. Empty: transparent fill, 2 dp `cs.outline` border. Filled: `cs.primary` fill, no border. Error: all four `cs.error` fill during the shake. |
| Submit | Auto-submits on the 4th digit, with no confirm button. Verification runs after the 4th dot has rendered (next frame). Keys ignore input while verifying. |
| Wrong entry | Dots row shakes horizontally (±8 dp, 3 cycles, 300 ms, `Curves.easeInOut`) in `cs.error`, `HapticFeedback.mediumImpact()`, then the dots clear. If `MediaQuery.disableAnimationsOf(context)` is true, skip the shake and show the error dots for 300 ms. |
| Cooldown (D-07) | All digit keys and backspace are disabled: `onTap: null`, label at `cs.onSurface` 38% opacity, key fill at `cs.onSurface` 12% opacity (M3 disabled convention). The status line counts down every second. The biometric key and "Esqueci meu PIN" stay **enabled** during cooldown, because they are not guessable. |
| Semantics | Each digit key has `Semantics(button: true, label: '1'…)`. The dots row is one `Semantics(label: l10n.lockDigitsEntered(count))`. The status line is `Semantics(liveRegion: true)` so TalkBack/VoiceOver announce errors and cooldown. |

### Lock screen (D-01, D-06, D-07, D-08)

Shown above everything: it covers every pushed route, dialog and bottom sheet. Mount it in `MaterialApp.builder` as a `Stack` layer above the Navigator child so no route can draw over it. No AppBar. `PopScope(canPop: false)`.

Layout: `Scaffold(backgroundColor: cs.surface)` → `SafeArea` → `Center` → `SingleChildScrollView` (so it does not overflow at 200% text scale) → `Column(mainAxisSize: min)`:

| Order | Element | Spec |
|-------|---------|------|
| 1 | Top spacer | `SizedBox(height: 48)` |
| 2 | Lock icon | `Icon(Icons.lock_outline, size: 48, color: cs.onSurfaceVariant)` |
| 3 | gap 16 | |
| 4 | Title | `lockEnterPinTitle`, `headlineSmall`, centered |
| 5 | gap 8 | |
| 6 | Status line | Fixed height 40, `bodyMedium`, centered, max 2 lines. Empty by default. Wrong PIN: `lockWrongPin(remaining)` in `cs.error`. Cooldown: `lockCooldown(m:ss)` in `cs.onSurfaceVariant`. Storage failure: `lockErrorGeneric` in `cs.error`. |
| 7 | gap 24 | |
| 8 | PinDots | see PinKeypad |
| 9 | gap 48 | |
| 10 | Keypad grid | see PinKeypad |
| 11 | gap 24 | |
| 12 | Forgot PIN | `TextButton(child: Text(lockForgotPin))` |
| 13 | Bottom | `SizedBox(height: 32)` |

Interaction:
- **Cold start (SC-1):** when `StorageKeys.pinConfigured` is true, the **first Flutter frame** is the lock screen. No app content may paint before it, even for one frame. When the privacy statement is still pending, no PIN can exist yet, so there is no ordering conflict.
- **Resume after timeout (D-01/D-02):** the lock screen replaces the privacy overlay directly, with no frame of app content in between. If the timeout has not elapsed, the overlay disappears and the app continues where it was.
- **App-initiated excursions (D-03):** returning from the file picker, an OS permission dialog or the `local_auth` sheet never shows the lock screen. It also never shows the keypad error state.
- **Biometric auto-prompt (D-08):** if biometrics are on and enrolled, call `local_auth.authenticate(localizedReason: l10n.lockBiometricReason, biometricOnly: true)` once after the lock screen's first frame. Success unlocks. Cancel or failure leaves the keypad visible with no extra message (the OS sheet already explained it). Tapping the biometric key re-opens the prompt.
- **Attempts (D-07):** after wrong PIN number n (n = 1–4), the status line shows `lockWrongPin(5 − n)`. The 5th wrong PIN starts a cooldown of 30 s, and each later failure after a cooldown escalates it to 1 min, 5 min, then 15 min (cap). Attempts and cooldown end persist across kills. Re-opening the app during cooldown shows the remaining countdown at once. A correct PIN, biometric success or a successful forgot-PIN flow resets the counter.
- **Unlock transition:** the lock layer fades out over 150 ms (`FadeTransition`). It disappears instantly when animations are disabled.
- **Forgot PIN (D-06):** tap calls `local_auth.authenticate(localizedReason: l10n.lockForgotReason, biometricOnly: false)`.
  - Success: push PIN setup in reset mode (create + confirm, no close button, no way back to the app until the new PIN is saved). Then show SnackBar `pinChangedSnack` and unlock. Data is kept.
  - Cancel/failure: return to the keypad silently.
  - Device has no screen-lock credential (`isDeviceSupported()` false): show the AlertDialog titled `lockForgotUnavailableTitle` with body `lockForgotUnavailableBody` and a single `TextButton(lockGotIt)`.

### PIN setup screen (create / confirm / change / verify / reset)

A full-screen route with the same column as the lock screen, minus the lock icon. It has an `AppBar` with a close `IconButton(Icons.close, tooltip: cancelButton)`, except in reset mode, which has no AppBar. The biometric key slot is always empty, and there is no "Esqueci meu PIN" button.

| Mode | AppBar title | Steps (title text, `headlineSmall`) | Success |
|------|--------------|-------------------------------------|---------|
| Create (switch OFF→ON) | `pinSetupTitle` | `pinCreatePrompt` → `pinConfirmPrompt` | Pop, switch ON, SnackBar `pinEnabledSnack` |
| Change | `lockChangePin` | `pinCurrentPrompt` → `pinCreatePrompt` → `pinConfirmPrompt` | Pop, SnackBar `pinChangedSnack` |
| Verify-to-disable | `lockPinToggle` | `pinCurrentPrompt` | Pop, switch OFF, SnackBar `pinDisabledSnack` |
| Reset (forgot PIN) | none | `pinCreatePrompt` → `pinConfirmPrompt` | Unlock app, SnackBar `pinChangedSnack` |

- Step changes cross-fade the title over 150 ms, and the dots clear.
- Confirm mismatch: status line shows `pinMismatch` in `cs.error`, the dots shake, and the flow returns to the create step.
- A wrong current PIN in change/verify mode uses the same `lockWrongPin` / cooldown behavior and counter as the lock screen.
- **No device screen lock (discretion, D-06 fallback):** before the create step, if `local_auth.isDeviceSupported()` is false, show the AlertDialog `pinNoDeviceLockTitle` / `pinNoDeviceLockBody` with actions `TextButton(cancelButton)` (abort, switch stays OFF) and `FilledButton(pinNoDeviceLockContinue)`.
- SnackBars use `behavior: SnackBarBehavior.floating`, matching `BackupScreen`.
