Build the security core every lock surface depends on: how a PIN is hashed, where the record
and the attempt state live, how a PIN attempt is verified against the D-07 ladder, and the
fresh-install wipe. Thin vertical path first: a PIN written through the real secure store
verifies through the real hasher.

are storage-level guarantees; DATA-05 is only as strong as this layer.

Output: domain contracts (PinRecord, PinHasher, PinStore), infrastructure (Pbkdf2PinHasher,
SecurePinStore), PinVerifier, DI wiring, startAppLock in main, test fakes and tests.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| App process -> Keystore/Keychain | PIN record and attempt state cross into platform secure storage. |
| Person holding the device -> verifier | Untrusted PIN guesses enter PinVerifier. |
| Previous install -> new install (iOS) | Keychain items survive an uninstall. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-05-07 | Information disclosure | PIN material in prefs, logs or failure text | high | mitigate | Record only in flutter_secure_storage via SecurePinStore; failures carry runtimeType only; secure_pin_store.dart has no SharedPreferences reference (acceptance grep). |
| T-05-08 | Information disclosure | Offline brute force of an extracted record (10^4 PIN space) | medium | accept | Inherent to a 4-digit PIN whatever the iteration count; protection is Keystore/Keychain encryption plus the online ladder. Isar is unencrypted at rest, so the lock is documented as a privacy gate, not encryption (RESEARCH Pattern 5 note). |
| T-05-09 | Tampering | Killing the app to reset the failure counter | high | mitigate | PinVerifier awaits writeAttempts before returning a rejection; attempts live in secure storage; pinned by pin_verifier_test ordering check. |
| T-05-10 | Tampering | Stale Keychain record or cooldown after iOS reinstall | medium | mitigate | startAppLock deletes all secure entries on a fresh install (no marker, no pin_configured); pinned by app_lock_startup_test. |
| T-05-11 | Information disclosure | Timing side channel in hash comparison | low | mitigate | constantTimeEquals with no early return; hashing in Isolate.run. |
| T-05-12 | Elevation of privilege | resetOnError wipe or corrupt record leading to fail-open | high | mitigate | Missing/malformed record or any storage Err yields PinCheckFailed, never PinVerified (user decision 1: fail closed); recovery is forgot-PIN (05-12). |
| T-05-SC | Tampering | npm/pip/cargo installs | high | accept | No package is added here; flutter_secure_storage and crypto were gated in 05-01. |
</threat_model>
