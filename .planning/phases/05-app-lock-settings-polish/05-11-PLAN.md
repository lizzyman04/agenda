## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| App -> OS biometric subsystem | local_auth hands identity verification to BiometricPrompt / LAContext. |
| Settings preference -> unlock path | biometric_unlock_enabled decides whether the prompt is offered. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-05-32 | Spoofing | Biometric spoofing (fake fingerprint or face) | medium | transfer | Matching is done by the OS biometric stack; unlock uses biometricOnly true; the PIN remains the fallback. |
| T-05-33 | Elevation of privilege | A biometric error or exception unlocking | high | mitigate | Only DeviceAuthResult.success unlocks; every exception maps to cancelled/unavailable/lockedOut; pinned by local_auth_gateway_test and app_lock_biometric_test. |
| T-05-34 | Denial of service | Prompt-induced lifecycle trip relocking in a loop | medium | mitigate | Every local_auth call is inside ExcursionGuard.run; locking is decided on hidden only (05-08); auto-prompt once per episode. |
| T-05-35 | Information disclosure | Prompt text leaking content | low | accept | The prompt shows only fixed localized strings; no user data is passed. |
| T-05-SC | Tampering | npm/pip/cargo installs | high | accept | local_auth was gated in 05-01; nothing is added here. |
</threat_model>
