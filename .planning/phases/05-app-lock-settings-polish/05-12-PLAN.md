<objective>
Let the user create, change, turn off and reset the PIN. Thin path first: PinSetupScreen in
create mode -> PIN + confirmation -> PinLifecycle.enable (record, window flag, flag last) ->
the next cold start is locked. Then change / verify / reset modes, then "Esqueci meu PIN" on the
lock screen through the device credential (D-06).

Purpose: DATA-05 "user can set an optional PIN"; D-06 forgot-PIN recovery keeps data; user
decision 1 makes forgot-PIN the only recovery when PIN material is lost.

Output: PinLifecycle, PinSetupCubit/State (new application/lock/setup nest), CooldownTicker
shared by both cubits, PinSetupScreen, the forgot-PIN flow and dialog, tests. The Settings
entry points are wired by 05-13.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Person holding the device -> PIN management | Changing, disabling or resetting the PIN. |
| App -> OS device credential | Forgot-PIN delegates identity to the device lock. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-05-36 | Elevation of privilege | Forgot-PIN reset without proving identity | high | mitigate | Reset is reachable only after DeviceAuthResult.success from the device credential (biometricOnly false); no device credential -> unavailable dialog, app stays locked (user decision 1); pinned by forgot_pin_test. |
| T-05-37 | Elevation of privilege | Changing or disabling the PIN without the current PIN | high | mitigate | Change and verify modes start with the current step verified by PinVerifier under the shared persisted ladder. |
| T-05-38 | Tampering | Crash between enable steps leaving a half-enabled lock | medium | mitigate | Enable writes pin_configured LAST and rolls back on failure; disable writes it FIRST; pinned by pin_lifecycle_test call-order checks. |
| T-05-39 | Denial of service | A new PIN starting in a stale cooldown | low | mitigate | enable, change and reset write LockAttempts.none with the record. |
| T-05-SC | Tampering | npm/pip/cargo installs | high | accept | No package is added by this plan. |
</threat_model>
