## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Path change silently unsorted 15 import blocks, adding new `directives_ordering` lints**

- **Found during:** Task 2, post-rewrite `flutter analyze`
- **Issue:** Renaming e.g. `domain/finance/transaction.dart` → `domain/finance/transaction/transaction.dart` changes the string's sort key, so import blocks that were alphabetical at baseline no longer were. This introduced 15 new info-level `directives_ordering` lints — lint debt created purely by a mechanical refactor.
- **Fix:** Ran `dart fix --apply --code=directives_ordering` on each affected file **individually** (never on `lib/` or `test/` wholesale), so only files this plan already modified were touched. Three files with pre-existing `directives_ordering` violations that this plan did *not* modify (`goals/screens/goal_list_screen.dart`, `screens/finance_dashboard_screen.dart`, `tasks/screens/task_list_screen.dart`) were deliberately left alone as out of scope.
- **Side effect:** `test/presentation/finance/budget_limit_sheet_test.dart` had one *pre-existing* ordering violation as well, which the same per-file fix cleaned up. Net analyzer count 82 → 65.
- **Files modified:** 15 (10 in `lib/`, 5 in `test/`)
- **Commit:** `1c0cb5a`

**2. [Rule 1 - Bug] One file regressed against `dart format` after the rewrite**

- **Found during:** Task 2, format-parity check against the baseline tree
- **Issue:** The longer nested path pushed `import '…/transaction/transaction_type.dart' as domain;` past 80 columns in `test/data/finance/transaction_mapper_test.dart`. Unlike a plain import, an `as`-aliased import *can* be wrapped, so `dart format` started wanting to change a file it had previously left alone — a real (if small) formatting regression.
- **Fix:** Hand-wrapped the `as domain;` clause onto a continuation line, matching exactly what `dart format` produces. Applied the same wrap to the two sibling occurrences in `lib/data/finance/transaction_mapper.dart` and `lib/data/finance/transaction_category_mapper.dart` for consistency.
- **Files modified:** 3
- **Commit:** `1c0cb5a`

### Documentation Deviation

**3. Updated a prose path reference the plan did not enumerate**

`lib/presentation/finance/goals/README.md` names `domain/finance/savings_goal.dart` in body text. The plan's file list covered code only, but leaving it would have left a stale path in a layer README *and* would have failed the acceptance grep. Updated to `domain/finance/goal/savings_goal.dart`. `lib/presentation/tasks/form/README.md` mentions only the directory `domain/finance/`, which is still correct, so it was left unchanged.

## Issues Encountered

- **`dart format --set-exit-if-changed` is not clean on `main`.** The execution brief stated it was. It is not — 103 of 258 files differ from `dart format` output at baseline, by deliberate project decision (STATE.md's "known tension", commit `a0869cc`). Running `dart format` as instructed would have reformatted ~103 unrelated files and pushed several past the 150-line architecture cap, breaking SC-1. This plan instead verified *format parity with baseline*, which is the check that actually protects the invariant. **06-18 should settle this**: either accept that `dart format` is not the project's formatter, or reconcile the 150-line cap with it.
- **Two new import URIs unavoidably exceed 80 columns.** `…/recurring/recurring_payment_repository.dart` (83 cols) and `…/category/transaction_category_repository.dart` (85 cols). A plain `import 'uri';` statement has no legal line break, so this cannot be fixed without renaming the files away from the plan's specified names. It is a non-issue for the enforced lint — `lines_longer_than_80_chars` exempts directive URIs, and its hit count is **0 both before and after** (verified by grepping the analyzer output, not by assumption). The raw count of >80-column lines in `lib/`+`test/` went 92 → 108; all 16 additions are import directives.
