## Critical Anti-Patterns

| Pattern | Description | Severity | Prevention Mechanism |

| Trusting a stale line reference in UAT/planning docs | Phase 06 relocated a large amount of code. `03-UAT.md` pointed at `task_detail_screen.dart:303` for a chip that had been extracted to its own file. This session it recurred twice more: my own 03-12 plan cited `widgets/budget_limit_sheet.dart` when the file is under `widgets/budget/`, and 03-09's plan claimed the target file was 124 lines when it was 140. | blocking | Re-resolve every `file:line` by reading the file before planning or acting against it. | Accepting a subagent's gate numbers without re-running them | Reported numbers have been right every time so far, but the whole phase's artifacts assert "65 infos" and "0 long lines" as load-bearing facts. | blocking | Re-run guard + analyze + test yourself, unpiped, after every plan. | Piped exit codes | `cmd \| tail` captures `tail`'s status in `$?`, so a failing gate can look like exit 0. | advisory | Run gate commands unpiped, or capture `${PIPESTATUS[0]}`. |
| Renaming a query's behaviour but not its name | 03-11 changed `getActivePayments` to stop filtering `isActive`. Leaving the name would have let a future aggregate trust "Active" and silently count paused rows. | advisory | When a query's meaning changes, rename it so every call site fails to compile and must be revisited. | Re-diagnosing already-diagnosed defects | Every open item in this phase has a confirmed root cause written down in `03-UAT.md` or `03-REVIEW.md`. | advisory | Read the recorded root cause first. Route already-diagnosed items straight to planning. |
