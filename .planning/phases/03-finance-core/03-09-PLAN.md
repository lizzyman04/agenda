<objective>
Close code-review finding CR-04 of `03-REVIEW.md` (Critical): the dashboard
balance silently goes wrong once a user passes 500 transactions, and never
recovers.

Root cause, confirmed by reading the source — do not re-diagnose:
`TransactionDao.findAll()` (`transaction_dao.dart:22-26`) is
`.filter().deletedAtIsNull().limit(500).findAll()` with **no `sortBy`**. Isar
returns rows in id order, so the cap keeps the *oldest* 500 and discards
everything newer. That result flows through
`TransactionRepositoryImpl.getTransactions()` (`transaction_repository_impl.dart:65`)
into `HomeDashboardCubit`, where it feeds `computeBalance` (line 80),
`computeNetWorth` (111) and `computeCategorySpend` (117).

So the headline balance, the net worth figure and the spending chart all stop
reflecting reality at transaction 501 and drift further every day the user
keeps logging. This directly falsifies phase 03's own success criterion 1
("the balance on the dashboard updates immediately").

Purpose: a personal-finance app whose balance is wrong is not usable. This is
the highest-severity finding in the phase.
</objective>
