  <action>
    Create `test/support/isar_test_harness.dart`.

    **Decision this task must record, in a top-of-file doc comment, explicitly and with
    rationale (this is the residual-risk decision the user asked to see stated, not
    silently assumed):**

    Route taken: **download-on-demand via `Isar.initializeIsarCore(download: true)`**,
    called once per test process behind an idempotency guard (a private top-level
    `bool _coreInitialized` flag, or equivalent), NOT a vendored/committed native binary.

    Rationale to write into the comment: `Isar.initializeIsarCore(download: true)` is
    isar_community's own documented mechanism for exactly this situation (opening Isar
    outside a running Flutter app), requires zero repository changes, and the binary it
    fetches is cached by the package itself so only the *first* invocation on a given
    machine needs network access. A vendored binary was considered and rejected: it would
    require committing a platform-specific native library (`.so`/`.dylib`/`.dll`) obtained
    by actually running the download once — something a planning-only pass cannot do and
    which is fragile because subsequent it would silently drift from whatever
    `isar_community` version is pinned in `pubspec.yaml`.

    Residual risk to write into the comment, explicitly: on a machine or CI runner with
    no cached Isar Core binary AND no network access, the first `flutter test` run that
    touches this harness will fail at `initializeIsarCore` with a download/network error.
    This is a **dev-toolchain** limitation, not a violation of CLAUDE.md's privacy/offline
    constraint — that constraint governs the shipped app's runtime behavior, and the
    shipped app never calls this method. State plainly that if this ever bites in CI, the
    fix is a pre-warmed cache or one manual network-enabled `flutter test` run, not a
    change to the app.

    **Implementation.** A class `IsarTestHarness` with two private fields, `Isar? _isar`
    and `Directory? _tempDir`, and this public surface:

    - `Isar? get isar` — the currently open instance, or null.
    - `Directory? get tempDir` — the temp directory backing the currently open instance,
      or null. Exposed so callers (and the Task 2 self-test) can assert on cleanup without
      needing to introspect the `Isar` instance's own directory API.
    - `Future<Isar> open(List<CollectionSchema<dynamic>> schemas) async` — calls the
      idempotency-guarded core-init, creates a fresh
      `Directory.systemTemp.createTempSync('agenda_isar_test_')`, opens
      `Isar.open(schemas, directory: <that dir's path>, name: <a value unique per call,
      e.g. derived from `DateTime.now().microsecondsSinceEpoch`>)` so two harness
      instances opened in the same process (parallel test files, or two tests in one
      file that both forget to close) never collide on instance name, stores both in the
      private fields, and returns the `Isar`.
    - `Future<void> close() async` — closes the instance with
      `await _isar?.close(deleteFromDisk: true)`, then defensively deletes `_tempDir` if
      it still exists (`if (_tempDir?.existsSync() ?? false) _tempDir!.deleteSync(recursive: true);`),
      then nulls both fields. Must be safe to call twice (idempotent) and safe to call
      without a prior `open()`.

    Every public member gets a one-line doc comment. All comments in English.
