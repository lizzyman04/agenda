<objective>
Close code-review finding CR-02 of `03-REVIEW.md` (Critical): pausing a
subscription hides it permanently.

Root cause, confirmed by reading the source — do not re-diagnose:
`recurring_payment_screen.dart:73-76` wires the card's toggle to
`updatePayment(payment.copyWith(isActive: !payment.isActive))`. The only query
behind that screen is `RecurringPaymentDao.findAll()`, which filters
`.isActiveEqualTo(true).and().deletedAtIsNull().limit(500)`.

So deactivating a payment removes it from the one list that renders it — and
the toggle that would switch it back is only rendered for rows the query still
returns. The user pauses a subscription, it vanishes, and there is no screen
anywhere that will show it again. `RecurringPaymentCubit.softDelete` has no
caller at all, so this toggle is effectively an undocumented delete.

Purpose: FIN-06 recurring payments are the bills a user is tracking. "Pause"
must mean pause, not "destroy silently".
</objective>

<design_decision>
The chosen approach is **show inactive payments in the same list, visually
distinguished**, rather than adding a filter control or a separate screen.

Rationale: it is the minimal change that makes the toggle reachable in both
directions, it preserves the existing single-list UI, and it matches how the
toggle is already presented (a per-row control, implying a per-row reversible
state). A filter chip would be more UI surface for the same outcome and would
still leave the default view hiding the paused rows.

If, while implementing, you find the screen already has a filter affordance
that makes a different approach obviously better, take it and record the
deviation in the SUMMARY with the reason.
</design_decision>
</context>
