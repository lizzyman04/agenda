<objective>
Close two findings from `03-REVIEW.md`.

**CR-03 (Critical) — the task-detail undo calls into a dead context.**
Root cause, confirmed by reading the source — do not re-diagnose:
`task_detail_screen.dart:40-56` pops the route
(`Navigator.of(context).pop()`) and THEN shows a SnackBar whose action closure
does `context.read<TaskListCubit>().restoreItem(item.id)`. By the time the user
taps Undo, up to `AppConstants.undoSnackbarDuration` (5s) later, that context
belongs to a defunct element. Ancestor lookup on a defunct element throws in
debug, and `restoreItem` never runs — the task the user asked to bring back
stays deleted.

The suite does not catch it: both existing tests let the SnackBar expire
without ever tapping Undo. The correct pattern is already in this codebase at
`transaction_list_screen.dart:44-45`, where plan 03-07 captured both the cubit
and the messenger into locals before touching navigation.

**WR-07 (Warning) — a fifth inline copy of the amount-parse bug.**
`budget_limit_sheet.dart:51-58` re-implements amount parsing inline instead of
calling the shared `parseAmountCentsOrNull`. Because of the known PT-BR
separator defect, a limit typed as `1.250,00` parses to null and the save
silently does nothing — the user sets a budget and it does not stick, with no
error shown.

Note the standing project decision: the root bug in
`lib/core/utils/amount_parser.dart` (thousands separators rejected, leading
minus stripped) is deliberately deferred to its own task and is NOT in scope
here. This plan removes the duplicate and makes the failure visible; it does
not fix the shared parser.
</objective>
