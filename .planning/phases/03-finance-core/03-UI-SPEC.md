## Spacing Scale

All values are `EdgeInsets` or `SizedBox` logical pixels. Must be multiples of 4.

| Token | Value | Flutter Usage |
|-------|-------|---------------|
| xs | 4 | `SizedBox(height: 4)` / `SizedBox(width: 4)` — chip internal gaps, tight inline spacing |
| sm | 8 | `SizedBox(height: 8)` / `EdgeInsets.all(8)` — card margin, chip run spacing |
| md | 16 | `EdgeInsets.symmetric(horizontal: 16)` — screen horizontal padding, card internal padding |
| lg | 24 | `SizedBox(height: 24)` — between major sections within a screen |
| xl | 32 | `SizedBox(height: 32)` — bottom of form body (scroll breathing room) |
| 2xl | 48 | `SizedBox(height: 48)` — chart section top/bottom margin |
| 3xl | 64 | Reserved for future large breakpoints |

Exceptions:
- Touch targets for icon buttons: minimum 48×48 logical pixels (Material 3 requirement)
- `Card.margin` for transaction/goal/debt list items: `EdgeInsets.symmetric(horizontal: 8, vertical: 4)` (matches Phase 2 `TaskCard` margin)
- `Divider` height inside cards: 1 logical pixel with `indent: 48, endIndent: 16` (matches Phase 2 `_FieldDivider`)
- Bottom sheet handle bar: `Container(width: 40, height: 4)` with `BorderRadius.circular(2)` (matches Phase 2 GTD guide pattern)
- Between form cards: `SizedBox(height: 12)` — 12px gap matches Phase 2 `task_form_screen.dart` card gap; intentional deviation from the 8/16 standard scale steps

## Typography

All roles map to `Theme.of(context).textTheme.*` — do not declare custom `TextStyle` sizes unless overriding a specific property (e.g., `copyWith(color: ...)`).

| Role | Flutter TextTheme Role | Approx Size | Weight | Line Height | Usage |
|------|----------------------|-------------|--------|-------------|-------|
| Display | `displaySmall` | ~36sp | w400 | 1.2 | Dashboard balance amount (e.g., "MT 12.450,00") — large size provides visual prominence without needing semibold |
| Headline | `titleLarge` | ~22sp | w400 | 1.2 | Screen section headers, empty state titles, GTD-style question headings |
| Title | `titleMedium` | ~16sp | w500 | 1.4 | Card titles (transaction title, goal name, debt counterparty) |
| Body | `bodyLarge` | ~16sp | w400 | 1.5 | Primary list item text, form field input text |
| Body secondary | `bodyMedium` | ~14sp | w400 | 1.5 | Subtitles, secondary labels, notes, date text |
| Label | `labelMedium` | ~12sp | w500 | 1.3 | Section header labels, field labels in form cards |
| Caption | `bodySmall` | ~12sp | w400 | 1.3 | Field label above value in ListTile (matches Phase 2 `bodySmall + onSurfaceVariant`) |
| Chip | Explicit `TextStyle(fontSize: 11)` | 11sp | w400 | — | Amount/date chips in transaction cards (matches Phase 2 `TaskCard` chip pattern) |

Weight rule: Use w400 (regular) and w500 (medium) only. Do not introduce w600, w700, or w300.
- w400: all body text, secondary text, chip text, display/headline roles
- w500: `titleMedium` and `labelMedium` roles (Material 3 defaults for those TextTheme roles)

## Color

Phase 3 inherits `ColorScheme.fromSeed(seedColor: Colors.deepPurple)` from Phase 2. Finance adds three semantic color aliases on top of the existing scheme.

### Base Scheme (inherited from Phase 2 — do not redeclare)

| Role | ColorScheme Token | Usage |
|------|------------------|-------|
| Dominant (60%) | `cs.surface` | Screen background (`Scaffold.backgroundColor`) |
| Secondary (30%) | `cs.surfaceContainerLow` | Card backgrounds, form section cards, bottom sheets |
| Primary accent | `cs.primary` | FAB background, FilledButton, active icons, progress bar fill, LinearProgressIndicator |
| Primary container | `cs.primaryContainer` | Highlighted action cards (matches Phase 2 GTD Guide Card) |
| Error/destructive | `cs.error` / `cs.errorContainer` | Delete confirmation buttons, overdue debt indicator |
| Surface variant | `cs.surfaceContainerHighest` | Inactive progress bar tracks, muted backgrounds |
| On-surface variant | `cs.onSurfaceVariant` | Secondary text, icon colors, dividers |
| Outline variant | `cs.outlineVariant` | Dividers inside cards, bottom sheet handle |

### Finance Semantic Colors (Phase 3 additions — define as constants in `lib/core/constants/finance_colors.dart`)

| Semantic Role | Value | Usage (exhaustive — do not use elsewhere) |
|---------------|-------|------------------------------------------|
| Income green | `Color(0xFF2E7D32)` | Income transaction amount text, income category icon, income row leading indicator dot |
| Expense red | `Color(0xFFC62828)` | Expense transaction amount text, expense row leading indicator dot |
| Warning amber | `Color(0xFFF57F17)` | Budget progress bar when spend reaches 80–99% of limit |
| Neutral (goals/debts) | `cs.primary` (inherited) | Savings goal progress bar, debt amount text (not income/expense semantic) |

**Accent reserved for (strict list):**
- `cs.primary`: FilledButton fill, FAB background, active NavigationBar icon/indicator, LinearProgressIndicator (budget normal state, goal progress)
- Income green: income amount text only — never backgrounds
- Expense red: expense amount text only — never backgrounds
- Warning amber: budget progress bar fill at 80–99% threshold only
- `cs.error`: budget progress bar fill at 100%+ only; destructive confirmation button fill

**Rule:** Income/expense semantic colors are text-only. They are never used as Card backgrounds, Container fills, or Chip backgrounds. Category-colored visual distinction uses the text color + a leading Icon, not a colored card.

## Number Formatting Contract

All monetary amounts are stored as `int` (cents). Display conversion uses `intl.NumberFormat`.

```dart
// lib/core/utils/amount_formatter.dart
String formatAmount(int amountCents, String currencySymbol, Locale locale) {
  final amount = amountCents / 100.0;
  final formatter = NumberFormat.currency(
    locale: locale.toString(), // 'pt_BR' or 'en'
    symbol: '',
    decimalDigits: 2,
  );
  return '$currencySymbol ${formatter.format(amount)}';
  // PT-BR: "MT 1.234,56"
  // EN:    "MT 1,234.56"
}
```

| Context | Format | Example (PT-BR) | Example (EN) |
|---------|--------|-----------------|--------------|
| Transaction card amount | `{symbol} {amount}` | MT 250,00 | MT 250.00 |
| Dashboard balance | `{symbol} {amount}` in `displaySmall` | MT 12.450,00 | MT 12,450.00 |
| Goal progress | `{saved} de {target}` | MT 6.800,00 de MT 10.000,00 | MT 6,800.00 of MT 10,000.00 |
| Budget progress | `{spent} / {limit}` | MT 450,00 / MT 1.000,00 | MT 450.00 / MT 1,000.00 |
| Chart axis labels | Not shown (labels hidden) | — | — |
| Chart legend | `{symbol} {amount}` | MT 320,00 | MT 320.00 |

**Currency symbol source:** `SharedPreferences.getString('userCurrency')` → parse to `Currency` object → use `currency.symbol`. Dev default: "MT" (MZN). Never hardcode "R$" or "$".

## Interaction Contracts

### Add Transaction Flow

1. User taps FAB on Transações tab → `TransactionFormScreen` pushed via `MaterialPageRoute`.
2. Form fields: type toggle (income/expense via `SegmentedButton`), amount field, category picker (BottomSheet), date picker, optional note field, optional goal link (if expense).
3. AppBar: `FilledButton("Salvar transação")` — calls Cubit on tap.
4. On success: pop screen. `TransactionListCubit` reloads via `watchLazy()` automatically.
5. On validation error: field border highlights (Material 3 default), `Text` error message below field.

### Delete Transaction Flow

1. Swipe `Dismissible` end-to-start OR tap `IconButton(Icons.delete_outline)` on detail screen.
2. For swipe: immediate soft-delete + SnackBar (`duration: AppConstants.undoSnackbarDuration`) with "Desfazer" action.
3. For detail screen delete: `AlertDialog` confirmation first (title: "Excluir transação?", body: "Esta ação removerá a transação permanentemente. Deseja continuar?", buttons: "Cancelar" + red "Excluir").
4. **Why the difference:** Swipe gives a 5-second undo window (soft delete already covers this). Detail screen delete triggers AlertDialog because the user is in a deliberate editing context — a single tap delete would be too easy to trigger accidentally.

### Add Goal Contribution Flow

1. User on goal detail screen taps `FilledButton.tonal("Adicionar contribuição")`.
2. `showModalBottomSheet` opens with: amount field, optional date field (defaults to today), optional note.
3. On save: `GoalCubit.addContribution()` — appends to embedded list and emits new state.
4. Goal detail rebuilds with updated progress bar and new contribution row in history list.

### Mark Debt as Paid Flow

1. `SwitchListTile` or `CheckboxListTile` on debt list item or detail screen.
2. No confirmation dialog — toggling paid/unpaid is reversible.
3. `DebtCubit.togglePaid(debtId)` — updates `isPaid` and `paidAt` fields.
4. Dashboard net worth recalculates on `watchLazy()` event.

### Budget Limit Set Flow

1. Budget Overview shows all expense categories. Tapping any row opens `ModalBottomSheet` with single amount field pre-filled with existing limit (or empty).
2. Save button in sheet calls `BudgetCubit.setLimit(categoryId, month, year, limitCents)`.
3. Sheet closes; budget row updates immediately.

## ARB Key Naming Convention

Finance ARB keys follow the same convention as Phase 2:

- Screens: `{domain}ScreenTitle` — e.g., `transactionListScreenTitle`
- Fields: `field{Name}` — e.g., `fieldAmount`, `fieldNote`, `fieldCategory`
- Empty states: `empty{Domain}`, `empty{Domain}Body` — e.g., `emptyTransactions`, `emptyTransactionsBody`
- Actions: verb + noun camelCase — e.g., `addTransaction`, `saveTransaction`, `deleteButton`
- Errors: `error{Context}` — e.g., `errorAmountRequired`, `errorSaveFailed`
- Categories (seed names): `category{Name}` — e.g., `categoryAlimentacao`, `categorySalario`

Default categories use l10n keys for the PT-BR seed names, but also store `namePtBr` directly on the model as a display fallback (per RESEARCH.md open question resolution: store both `namePtBr` and `nameEn` on `TransactionCategoryModel`).
