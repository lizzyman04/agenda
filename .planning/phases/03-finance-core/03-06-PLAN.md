<objective>
Close UAT test 2 (severity: major). Transaction cards in the Transações list
render the raw category id (`#10`, `#1`, `#2`) instead of the category name,
and a note that differs from the category name renders twice on the same card.

Root cause (already diagnosed in 03-UAT.md, do not re-diagnose):
`transaction_list_screen.dart`'s `_categoryName` is an unfinished stub that
always returns `'#${tx.categoryId}'` — categories are never fetched into the
screen. Separately, `transaction_card.dart` puts `transaction.note ?? categoryName`
in the `ListTile` title AND repeats the same note in a `Chip` below the subtitle.

Purpose: the transaction list is the primary read surface for FIN-01/FIN-02.
A user cannot tell an expense apart from another without the category name.
Output: `TransactionLoaded` carries the category list (mirroring `BudgetLoaded`),
the list screen resolves names via the existing `resolveCategoryDisplay` helper,
the card renders each piece of information exactly once, and two new widget
tests lock both behaviours in.
</objective>
