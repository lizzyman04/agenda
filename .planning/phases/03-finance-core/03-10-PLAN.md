<objective>
Close code-review finding CR-01 of `03-REVIEW.md` (Critical): swiping a debt
away destroys it with no way back.

Root cause, confirmed by reading the source — do not re-diagnose:
`debt_card.dart:37` wraps the row in a `Dismissible` with
`DismissDirection.endToStart` and `onDismissed: (_) => onDelete()` (line 49).
There is **no `confirmDismiss`**. `debt_list_screen.dart:73-74` wires that
straight to `ctx.read<DebtCubit>().softDelete(debt.id)`, and there is **no
SnackBar and no undo**. `DebtCubit` exposes `start`, `createDebt`,
`updateDebt`, `togglePaid`, `softDelete` and `_reload` — **no restore method
exists at any layer**.

So one stray horizontal drag sets `deletedAt` on a real debt and strands the
row in Isar, unreachable from every screen in the app. There is no undo window
to miss; the recovery path was never built.

The fix has a proven local precedent. `TransactionCubit.restoreTransaction`
(`transaction_cubit.dart:86-98`) does get → `copyWith(deletedAt: null)` →
update, with a silent return when the record is already gone. `Debt.copyWith`
already carries the same `clearField` sentinel for `deletedAt`
(`debt.dart:73`), so `debt.copyWith(deletedAt: null)` genuinely clears the
tombstone rather than being read as "not provided". No new repository or DAO
method is required.

Purpose: FIN-05 debts are money owed and owing. Silent unrecoverable deletion
of a financial record is the most damaging class of bug this app can have.
</objective>
